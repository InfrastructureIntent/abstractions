## Iteration logging policy update

The Abstractions agent contract was tightened directly on `main` to make iteration logging an execution gate rather than a closeout-only activity.

The repository now requires:

- today's iteration log to be created or updated before substantive work;
- meaningful decisions, implementation results, validation outcomes, review findings, merges/releases, blockers, and architecture implications to be recorded as they occur;
- today's log to be explicitly checked for completeness before repository work is declared complete;
- exactly one iteration log per repository per calendar day;
- today's work never to be appended to a previous day's log;
- separate daily records when work moves between repositories.

This clarification is recorded under `[Unreleased]` in `CHANGELOG.md` and does not change the public Abstractions contract surface.
